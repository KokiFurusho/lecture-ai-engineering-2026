## 宿題

- 取り組んだレベル：実装
- 使ったモデル：gemini-3.5-flash-lite（既定。`AIE_MODEL` は変えていない）
- やったこと：
  - `app/ask.py` に `--chat` オプションを追加し、会話履歴を保ったまま続けて質問できるようにした
    ```bash
    uv run python -m app.ask --chat
    ```
  - `client.chats.create(model=MODEL)` で Chat を作り、`chat.send_message()` で質問する。Chat が質問と回答を履歴として持ち、次の質問のときに履歴ごとモデルに送る
  - 空行・`exit`・`quit`・Ctrl-D で終了する。レート制限（429）などの API エラーが出ても終了せず、それまでの履歴を残したまま次の質問を続けられる
  - 1回ごとの回答のあとにトークン数を表示する
  - `tests/test_ask.py` を追加した。API を呼ばない偽の Models を google-genai の本物の Chat に渡し、2回目の質問のときに1回目の質問と回答も一緒に送られていることを確かめる（API キー不要）
- 結果：
  - `uv run pytest -q` で、追加した `tests/test_ask.py` を含むテストが通った
  - 実際の API での会話：「私はこうきです。」→「私の名前は？」と続けて質問したところ、「あなたの名前は「こうき」さんです！」と答え、1回目の内容を覚えていた
  - 入力トークン数の変化：1回目は 入力 6 / 出力 46、2回目は 入力 58 / 出力 10。2回目の入力 58 は、1回目の質問（6）＋1回目の回答（46）＋2回目の質問（約6）にほぼ一致し、履歴をまるごと送り直していることが数字で確認できた
- 気づき・疑問：
  - 会話履歴は「モデルが覚えている」のではなく、毎回すべての履歴を入力として送り直している。そのため会話が長くなるほど入力トークン数が増え、無料枠のトークン上限やコストに効いてくる
  - 長い会話では、古い履歴を捨てる・要約するなどの工夫が必要になりそう
